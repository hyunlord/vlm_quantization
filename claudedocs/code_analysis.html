01목적과 아키텍처

단일 투영에서 여러 비트 길이를 prefix로 잘라 쓰는 Matryoshka 구조 — 짧은 코드가 긴 코드의 접두사가 되어 coarse-to-fine 검색이 가능합니다. backbone은 frozen/fine-tune 양쪽 지원.

핵심 설계

  • Matryoshka prefix-nesting — 단일 head + 비트별 BN으로 6개 해상도를 파라미터 효율적으로 생성
  • SignSTE — sign 이진화 + |x|≤1 구간만 gradient 통과(클리핑 STE)
  • 모달리티별 분리 head — image/text 각각 NestedHashLayer

정직한 평가

  • frozen-backbone cosine mAP를 해시 mAP와 병행 로깅 — 해싱 이득을 원본 임베딩과 직접 비교
  • frozen 시 baseline 메트릭 캐싱(임베딩 불변)
  • supervised 멀티핫 라벨 경로로 진짜 카테고리 mAP 측정 가능

실전 성숙도

  • GPU 자동 배치 — VRAM·통합메모리(DGX Spark GB10) 감지
  • spawn 멀티프로세싱으로 CUDA fork 데드락 회피
  • FastAPI+SQLite+Next.js 대시보드 · Optuna HPO

02손실 오케스트레이션 로직

CombinedHashLoss는 비트 길이마다 5개 손실을 합산하고, 비트 길이 전역으로 LCS 자기증류를 더합니다. contrastive는 원본·약증강·강증강·보조캡션 뷰 수(n_views)로 평균됩니다.

손실역할스코프가중치
InfoNCE contrastive대칭 교차엔트로피. focal_gamma로 쉬운 positive 다운웨이트(0이면 plain과 동일)비트별 × 뷰1.0
OrthoHash매칭쌍 cos→1, 비매칭→0비트별 교차모달0.1
EAQL quantEMA 비트중요도 가중 양자화 오차 · 램프업 · 이제 train에서만 EMA 갱신비트별 양모달0.1
BitBalance비트 50/50 균형 + 비트간 탈상관(공분산≈I)비트별 joint0.01
Consistency원본↔증강 이미지 코드 MSE 정렬비트별0.5
LCS self-distill긴 코드(teacher)→짧은 코드(student) 유사도 구조 증류전역(인접 비트쌍)0.5
Supervised optional멀티핫 라벨 pairwise log-sigmoid(라벨 있을 때만)비트별0.0

✅ 정합성 — 강점

  • 뷰 평균 일관성: n_views가 매 비트 반복마다 동일하게 증가 → 정확
  • 증류 정규화: LCS가 행 단위 정규화해 긴 코드의 큰 내적이 MSE를 지배하지 않도록 방지
  • EAQL EMA를 state_dict 버퍼로 등록 → device 이동/체크포인트 보존
  • quant 램프업으로 초반 표현 학습 우선

이번 라운드 로직 보강

  • EAQL 검증 누수 차단 — self.training 가드로 검증 배치가 EMA 비트가중치를 더 이상 오염시키지 않음(학습 경로는 byte-identical 검증)
  • 벡터화 메트릭 — mAP/P@K/R@K의 쿼리별 Python 루프를 청크 텐서연산으로 교체, 브루트포스 대조 테스트로 동치 확인
  • 검증 mAP 라벨은 여전히 image_id 기반(짝 1개) — 진짜 카테고리 mAP는 instances_json 필요(다음 단계)
