⑦ 텍스트→이미지 (t2i) 검색 예시 — 실제 사용 시나리오

하드타입 텍스트 쿼리로 OI 167K 코퍼스 검색. 각 행 = float(정답기준) / bit-old(옛 데모, raw 입력) / bit-base(정규화 COCO 재학습) / bit-CC12M의 top-10. 괄호=float top-10 겹침.

⚠ 정정 (통제 ablation, 2026-06-17): 아래 "정규화가 running-lab을 고쳤다"는 이전 해석은 틀렸습니다. COCO-only·seed=42·동일 HP/EPOCHS·해시입력 정규화만 on/off로 토글한 통제 실험(scripts/train_ablate.py) 결과 — 정규화(NORM)도 비정규화(RAW)도 둘 다 "달리는 개"를 반환(NORM 4/4, RAW 3/4). 즉 정규화는 이 gross 오류를 뒤집지 않습니다. bit-old(옛 데모)의 "도서관"은 정규화 유무가 아니라 옛 레시피 전체(HP·손실구성·aug·Matryoshka 부재) 때문이고, 현재 레시피는 정규화 여부와 무관하게 개를 냅니다. 정규화의 진짜 효과 = 집계 agreement@100: NORM 20.0% vs RAW 10.9% (~2배) — 정답성(R@10 0.774 vs 0.779 거의 동일)이 아니라 float 랭킹 일치도를 올립니다. 교훈: 단일 손쿼리로 인과를 귀속하지 말 것 — 통제 ablation 필수.

⑧ 이미지→이미지 (i2i) 검색 예시 — 참고 (씨앗 제외 top-10)

씨앗 이미지를 쿼리로 float(정답기준) / bit-baseline / bit-CC12M이 각각 무엇을 가져오는지. 금색 테두리=씨앗(rank1). 괄호=float top-8과의 겹침.
⚠️ 이건 i2i(이미지→이미지)라 텍스트쿼리 agreement와 다른 regime — CC12M 우위가 i2i에선 덜 뚜렷할 수 있음(정직히 표기).

⑪ 정직한 단서

  • cross-round agreement 직접 비교 불가: robust 평가 쿼리를 학습데이터 캡션에서 샘플 → 라운드마다 쿼리분포 상이(OI캡션 vs CC12M캡션). 엄밀한 건 같은 run 내(17.6→34.7).
  • 절대 agreement 여전히 낮음(34.7%): hash가 float top-100의 ~1/3만 맞춤 — 격차 크게 남음. 단 궤적(데이터↑→개선) 분명.
  • "running lab" 극단 다의어는 0→8%로 거의 안 풀림 — 1-bit+소형head 본질 한계.
  • 갤러리(⑦)는 i2i라 텍스트쿼리 결과와 다름. 진행 중: CC12M ~800K 확장·전 데이터 결합.
