# Gap B 정밀 해부 — 핸드오프 (중립 관찰 + ⚠ 예상과 다른 점)

**대상 가설(Gap B)**: "frozen VLM 검색정보는 *소수 연속 차원*에 집중, 저비트 압축 손실은 *차원이 아닌 이진화 방식*에서 온다."

**방법**: 캐시된 raw frozen 임베딩(학습 head 없이)을 PCA로 d∈{2..D} 줄여가며 cross-modal R@10 측정. 코딩 모드 = 연속(cosine)/sign(1-bit)/sign_mc(모달별 평균제거 후 sign)/asymmetric(쿼리=연속·갤러리=1-bit)/2-bit. 학습된 matryoshka head 곡선을 별도로 겹쳐 비교. 견고성: 3개 frozen backbone(so400m 1152-d, siglip2-base 768-d, altclip-m18 1024-d) + XM3600 36언어. COCO 5K(대각 gold), XM3600(텍스트→이미지 gold). 새 학습 없음.

산출: `paper/gapB_*.csv`, `viz/data/gapB_*.json`, `viz/{dim_vs_recall,bits_vs_dims_heatmap,spectrum_explorer,pc_contribution,lang_saturation}.html`. 보기: `cd viz && python3 serve.py`.

## 견고하게 성립한 것 (3 backbone + 36언어 일관) ✓

### 1. 손실의 원인 = 이진화, 차원 아님 ✓✓ (가장 강함)
- 연속(cosine)은 차원 축소에 **관대**: 저분산 차원은 magnitude로 자동 가중되어 ~0 기여 → 차원을 늘려도 안 무너짐(so400m 연속 256→1152: 79.9→80.6, 평평).
- 1-bit·2-bit는 **모든 차원에 동일 가중(±1)** → 저분산 차원이 Hamming/양자화에 순수 잡음을 주입. 결과: **이진 코드는 최적 차원이 존재하고 그 뒤 붕괴**.
  - so400m raw sign: d=256에서 정점 **48.7** → d=1152에서 **4.2**.
  - so400m raw 2-bit: d=128에서 정점 **65** → d=1152에서 **11**.
- 같은 총비트 예산(≈256bit): 2-bit×128차원(**65**) > 1-bit×256차원(**49**) > float×8차원(**3.6**) → "차원 축소"보다 "이진화"가 손실 지점. (`bits_vs_dims_heatmap.html`)

### 2. asymmetric(쿼리 연속 × 갤러리 1-bit)이 손실의 상당량 회수 ✓
- raw에서도 so400m: sign 4.2 → asym **69.1**(연속 천장 80.6 대비). 쿼리만 연속으로 두면 잡음 차원이 다시 magnitude로 가중됨. 3 backbone 공통.

### 3. 연속 검색의 차원은 ~256(¼·D)에서 포화, backbone·언어 불변 ✓
- raw 연속 99% 도달 차원: so400m **256**, siglip2-base **256**, altclip-m18 **512**(95%는 256). 누적분산 90%@~240차원.
- XM3600 36언어 saturation 차원 중앙값 **256**(라틴/비라틴 공통, 범위 128-512). 언어 차이는 차원이 아니라 **최종 성능**(de~97 vs 일부 비라틴 더 낮음). (`lang_saturation.html`)

### 4. 공유 저차원 부분공간은 일부 실재 — 단 비대칭 (Section 3) ✓/⚠
- **이미지↔텍스트 부분공간**: top-k PCA 주각 겹침(cos² 평균) @64 ≈ 0.39~0.45(random 0.05~0.08의 **6~8배**), @256 ~0.6 → 부분 공유, 동일하진 않음. 3 backbone 일관. (`subspace_overlap.html`)
- **★ 비대칭**: 교차모달 검색 신호는 **텍스트 주성분 부분공간**에 훨씬 더 정렬됩니다. 두 모달을 텍스트 basis에 투영한 R@10 ≈ 결합 basis(so400m@64 66.6 vs 결합 63.2)지만, 이미지 basis에 투영하면 27.7로 급락 → 이미지의 고분산 방향은 검색 방향이 아님(spectrum의 PC#0 관찰과 일치).
- **언어 간**: XM3600 36언어의 텍스트 부분공간은 영어와 강하게 공유(vs_en 중앙값 **0.67**@64), 이미지와의 공유(vs_img 0.33)보다 큼 → 다국어가 *공통 텍스트 저차원 부분공간*을 씀. 약한 언어(te 0.13, mi 0.09)는 공유가 낮음 → 약함 = 공통 부분공간 밖.

## ⚠ 예상과 다른 점 (가설을 약화/수정) — 정직 플래그

### A. ⚠ "소수 차원 집중"은 raw 임베딩에선 과장 — 그 집중은 **head가 만든다**
- 가설의 단서였던 Part1 "64-d 연속 ≈ 80.4"는 **학습된 head의 z**였음. 같은 64차원을 **raw PCA**로 보면 so400m **63.2**뿐(천장 80.6의 78%). raw는 천장에 ~256차원 필요.
- 학습 head는 d=**64**에서 이미 천장(so400m 80.4 / siglip2 78.3 / altclip 78.6), d=**32**에서도 ~96%. **3 backbone 모두** head가 정보를 저차원으로 압축. raw sign 4~12% → head sign **78~80**(비트수에 단조 증가, 붕괴 없음).
- ∴ "frozen VLM 고유의 소수 차원 집중"은 **부정확**. frozen raw는 ~256차원(중간 정도 저차원). 극적 집중과 이진화 친화성은 **matryoshka head 학습의 산물**. → 베팅 시 "intrinsic 저차원" 프레이밍은 약화, "head가 만드는 압축·이진화 친화성"이 실제 레버.

### B. ⚠ "검색기여순 ≠ 분산순"은 약하게만 성립 (단독 PC 신호가 바닥)
- 각 PC를 **단독**으로 쓴 R@10이 **모두 바닥(~0.4%)** — PC#0(분산 **29%**)조차 단독 검색 ~0.2%. 즉 검색은 소수 PC 집중이 아니라 중간 스펙트럼 전반에 **분산**.
- 진짜 또렷한 비대칭은 **PC#0(고분산·무검색)** 한 사례: 분산 큰 방향 ≠ 검색 중요 방향(아마 nuisance/모달 축). 하지만 어떤 저분산 PC가 결정적이지도 않음.
- 분산순 vs 검색기여순 누적 곡선은 거의 겹치고 256에서 수렴(Spearman 0.66~0.72). 검색기여순이 초반 약간 빠르나(32 PC: 44 vs 37) 단독 신호가 약해 순위 자체가 불안정. → "검색기여순≠분산순"이 *새로움*이려면 더 강한 증거 필요. 현재는 약함.

### C. ⚠ sign_mc ≈ sign — 모달 갭(평균 차이)은 raw sign 붕괴의 주원인 아님
- 모달별 per-dim 평균 제거 후 sign(`sign_mc`)도 sign과 거의 동일(so400m 4.0 vs 4.2). raw sign 붕괴는 단순 평균 오프셋이 아니라 모달 간 부호 패턴 자체의 비정렬 → head가 푸는 문제.

### D. (관찰) I2T ≠ T2I 비대칭은 backbone 특성
- so400m T2I/I2T = 80.6/38.4, siglip2 78/16(SigLIP 계열 hubness), altclip 78.5/80.1(대칭). Gap B 현상과 무관한 backbone 고유 성질로 보임. 헤드라인은 T2I(Part1과 일치) 기준.

## 종합 판단 (베팅 관점, 단정 아님)
- **견고**: 이진화가 병목이라는 핵심은 3 backbone·다국어에서 강하게 성립. 이진 코드의 최적 차원·고차원 붕괴·asymmetric 회수도 일관. 실배포 시사: 저비트라면 차원을 무한정 늘리지 말고 정보 있는 ~128-256차원에 비트 집중 + 가능하면 asymmetric.
- **수정 필요**: "frozen VLM이 본래 소수 차원에 검색정보를 집중"이라는 프레이밍은 raw 증거로 **약화**됨(~256차원). 극적 저차원성은 **head 학습 효과**. "검색기여순≠분산순" 새로움은 PC#0 사례 외엔 약함.
- 한 backbone의 우연 아님(패턴 일관) → 현상의 *견고한 부분*은 베팅 가치 있음. 단, *새로움의 핵심*을 "intrinsic 저차원 집중"에 두면 깨질 위험. "이진화 병목 + head가 만드는 압축/이진화 친화성"으로 재프레이밍 권고.
